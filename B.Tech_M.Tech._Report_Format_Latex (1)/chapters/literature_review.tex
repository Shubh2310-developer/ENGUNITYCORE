\chapter{Literature Review}
\label{chap:litrev}

The design of Engunity~X is grounded in four major technical lineages: retrieval-augmented generation and its advanced variants, autonomous reasoning agents, multimodal perception systems, and secure code execution infrastructure. This chapter surveys each lineage, traces key research contributions that directly influenced design decisions, and closes with a gap analysis situating Engunity~X relative to the most closely related prior work.

\section{Retrieval-Augmented Generation: Foundations and Evolution}
\label{sec:rag-survey}

\subsection{Naive RAG: The Foundational Paradigm}
\label{subsec:naive-rag}

The retrieval-augmented generation paradigm was formalised by \citet{lewis2020rag}, who demonstrated that open-domain question answering could be substantially improved by combining a neural retriever (DPR~\citep{karpukhin2020dpr}) with a sequence-to-sequence generator (BART). On Natural Questions and TriviaQA benchmarks, this approach outperformed GPT-3 on closed-book QA by substantial margins. The core insight---grounding generation in retrieved evidence reduces hallucination and enables access to knowledge beyond training data---spawned a large ecosystem of variants.

\subsection{Advanced RAG Variants}
\label{subsec:advanced-rag}

The limitations of naive RAG are well-characterised: retrieval quality is a hard ceiling on generation quality, retrieved passages may be only loosely relevant, and the finite context window cannot accommodate all retrieved content.

\subsubsection{HyDE: Hypothetical Document Embeddings}
\citet{gao2022precise} observed that query embeddings are often geometrically far from the answer document embeddings. Their solution, HyDE, uses the LLM to generate a hypothetical answer document, then retrieves based on that embedding. On several BEIR benchmarks, HyDE improved nDCG@10 by 5--10 percentage points. Engunity's OmniRAG implements HyDE in the single-hop path, particularly effective for engineering queries where question vocabulary differs from answer passage vocabulary.

\subsubsection{CRAG: Corrective Retrieval-Augmented Generation}
\citet{yan2024crag} identified that when retrieved documents are poor, generators produce unreliable output with no failure signal. CRAG inserts a lightweight confidence evaluator; if confidence falls below a threshold, a web-search fallback is triggered. In Engunity, the \texttt{crag\_evaluator} uses a cross-attention scorer with a 0.6 threshold, falling back to Brave Search API when local retrieval is insufficient.

\subsubsection{GraphRAG: Graph-Based Community Summarization}
\citet{edge2024local} proposed GraphRAG to address vector RAG's fundamental limitation on synthesis queries. It builds a knowledge graph, partitions into communities via Louvain algorithm, generates community summaries, and performs map-reduce retrieval over those summaries. Engunity adopts this approach for the multi-hop path, with knowledge graphs built via SpaCy NER and background Celery workers generating summaries stored in MongoDB.

\subsection{Modular RAG and the Pipeline Paradigm}
\label{subsec:modular-rag}

The modular RAG framework~\citep{gao2023modularrag} reconceptualised RAG as a configurable pipeline of interchangeable modules (query rewriter, retriever, re-ranker, compressor, generator, evaluator). This framework provides the principled basis for OmniRAG's routing logic: different query complexity tiers activate different subsets of available modules.

\section{Autonomous Agents and Iterative Reasoning}
\label{sec:agents-survey}

\subsection{The ReAct Framework}
\label{subsec:react}

\citet{yao2022react} introduced ReAct (Reason+Act), which interleaves reasoning traces with actions and observations. On HotpotQA, Fever, and AlfWorld benchmarks, ReAct substantially outperformed both chain-of-thought reasoning alone and task-specific supervised models. Engunity's DeepResearchAgent is built on this loop: each iteration generates a reasoning trace, selects an action, executes it, and updates its evidence pool, with the trace streamed to the user in real time.

\subsection{Multi-Agent Role Specialisation}
\label{subsec:autogen}

\citet{wu2023autogen} introduced AutoGen, a framework where multiple LLM-backed agents with distinct system prompts collaborate to solve complex tasks. Role specialisation---planner, executor, critic---substantially outperforms single-agent approaches on software engineering tasks. Engunity adopts this pattern in the DeepResearchAgent's synthesis phase with a \texttt{PlannerAgent}, \texttt{SearchAgent}, and \texttt{CritiqueAgent}.

\subsection{Reflexion: Verbal Reinforcement Learning}
\label{subsec:reflexion}

\citet{shinn2023reflexion} proposed Reflexion, in which an agent generates verbal feedback on failed actions and conditions subsequent attempts on prior reflections, achieving state-of-the-art performance on HumanEval and WebArena. Engunity's \texttt{SelfCritique} module implements this loop: responses scoring below 1.8/3.0 on relevance, completeness, and groundedness are regenerated with the critique attached. One critique iteration was sufficient in over 90\% of cases.

\section{Multimodal Perception Systems}
\label{sec:multimodal-survey}

\subsection{CLIP: Cross-Modal Embedding}
\label{subsec:clip}

\citet{radford2021clip} trained a vision encoder (ViT) and text encoder jointly on 400 million image-text pairs, creating a shared 512-dimensional embedding space. For Engunity, the critical property is this shared space: uploaded images are embedded alongside text chunks in the same FAISS index, enabling cross-modal retrieval without a separate image retrieval pipeline.

\subsection{YOLOv8: Real-Time Object Detection}
\label{subsec:yolo}

\citet{jocher2023yolov8} released YOLOv8n, which achieves 37.3 mAP at 80.4 FPS on COCO using only 3.2M parameters---suitable for CPU deployment. Engunity uses YOLOv8n to detect and label objects in uploaded images; detected labels supplement CLIP embeddings with symbolic object identifiers for improved technical documentation matching.

\subsection{OCR for Engineering Handwriting}
\label{subsec:ocr}

EasyOCR~\citep{easyocr2020} is a multi-language OCR engine handling both printed and handwritten text with layout information. Engunity uses EasyOCR with layout-preserving output: detected text regions are returned with bounding box coordinates, preserving spatial relationships important for matrix equations and multi-line derivations.

\section{Secure Code Execution Infrastructure}
\label{sec:sandbox-survey}

The secure sandboxing problem has been studied extensively in online judge systems. Common approaches include chroot jails, Linux namespaces, cgroups, seccomp filters, and Docker containers. Judge0~\citep{judge0} and Piston~\citep{piston} are open-source execution APIs designed for competitive programming---prioritising security and throughput over interactive debugging. Engunity's Code Lab takes a different approach: a custom \texttt{SecureSandbox} class managing Docker containers directly via the Docker SDK, enabling the interactive WebSocket terminal sessions that batch-oriented APIs cannot support.

Monaco Editor provides the browser-based IDE, supporting syntax highlighting for 80+ languages and a rich API for programmatic control. Engunity extends Monaco's completion API to query the OmniRAG pipeline, enabling completions informed by the user's uploaded documents.

\section{Pedagogical and UX Considerations}
\label{sec:pedagogy}

Sweller's Cognitive Load Theory~\citep{sweller1988cognitive} implies that reducing extraneous load (poor interface design, unnecessary complexity) frees cognitive capacity for germane load (productive learning effort). Engunity's single unified chat interface, automatic query complexity classification, and persistent memory system each target a specific source of extraneous load identified in the educational psychology literature. The long-term user profile functions as a simplified learner model from the Intelligent Tutoring System literature~\citep{ma2014intelligent}, adapting explanations to the user's apparent expertise level.

\section{Summary}
\label{sec:litrev-summary}

This chapter has surveyed the four technical lineages informing Engunity~X's design. RAG has evolved from naive dense retrieval to modular adaptive pipelines; Engunity incorporates CRAG, HyDE, and GraphRAG within its OmniRAG router. The autonomous agents literature (ReAct, AutoGen, Reflexion) shapes the DeepResearchAgent's architecture. CLIP, YOLOv8n, and EasyOCR form the multimodal perception stack. Docker-based sandboxing with WebSocket interactivity advances beyond static batch-execution APIs. The research gap analysis confirms Engunity~X's integrated six-capability architecture is novel. Chapter~\ref{chap:design} describes how each component is designed and implemented.
